# Tailwind CSS + Lucide Icons Dashboard Rewrite

## Overview

Replace Bulma CSS with Tailwind CSS v4 + Lucide icons in the CEMS Knowledge Engine
dashboard. The current Bulma-based UI looks generic and cheap. Tailwind gives us
full control over the design with a modern, polished dark theme.

No framework change — stays vanilla JS. No new build pipeline in CI or Docker.
Pre-build CSS locally with the Tailwind CLI standalone binary, commit the output.

## Problem Statement

The Bulma CSS dashboard looks like a default template. Bulma's component-first
approach limits customization without fighting the framework. Emoji icons (📖, 🗒️)
look unprofessional. The UI needs to feel like a modern product, not a prototype.

## Technical Approach

### Build Strategy: Pre-built CSS (Zero Runtime Dependency)

```
Development:                      Production:
┌─────────────┐                   ┌─────────────┐
│ input.css   │──tailwindcss──>   │ style.css   │  ← committed to git
│ index.html  │   (standalone)    │             │
│ app.js      │                   │             │
└─────────────┘                   └─────────────┘
                                        │
                                  ┌─────┴──────┐
                                  │ Starlette   │  ← serves static files
                                  │ StaticFiles │     (no change)
                                  └────────────┘
```

**Tailwind CSS v4 standalone CLI** — single binary, no Node.js:
```bash
# macOS ARM64
curl -sLo tailwindcss https://github.com/tailwindlabs/tailwindcss/releases/latest/download/tailwindcss-macos-arm64
chmod +x tailwindcss

# Build for production
./tailwindcss -i src/cems/static/wiki/input.css -o src/cems/static/wiki/style.css --minify

# Watch during development
./tailwindcss -i src/cems/static/wiki/input.css -o src/cems/static/wiki/style.css --watch
```

Alternative: `pip install pytailwindcss` (wraps the same binary).

**input.css** (Tailwind entry point):
```css
@import "tailwindcss";

/* Custom CSS variables for heat colors, graph, etc. */
@theme {
  --color-hot: #ef4444;
  --color-warm: #f59e0b;
  --color-cool: #3b82f6;
  --color-cold: #6b7280;
}
```

**Docker**: No change. `COPY src/ src/` copies the pre-built `style.css`.
**CI**: No change. CSS is committed to git — no build step needed.

### Lucide Icons via CDN

```html
<script src="https://unpkg.com/lucide@latest/dist/umd/lucide.js"></script>
```

Usage:
```html
<i data-lucide="book-open"></i>      <!-- Wiki -->
<i data-lucide="brain"></i>          <!-- Memories -->
<i data-lucide="network"></i>        <!-- Graph -->
<i data-lucide="bar-chart-3"></i>    <!-- Stats -->
<i data-lucide="heart-pulse"></i>    <!-- Health -->
```

After dynamic DOM updates: `lucide.createIcons()`.

### Dark Theme

Tailwind v4 dark mode via `prefers-color-scheme` (automatic) plus a `dark` class
on `<html>` for explicit control. All colors use Tailwind's dark palette:
- Background: `bg-gray-950` (main), `bg-gray-900` (sidebar/cards)
- Text: `text-gray-100` (primary), `text-gray-400` (secondary)
- Borders: `border-gray-800`
- Accent: `text-blue-500`, `bg-blue-600` (links, active states)

### 9. Build helper script (NEW — `scripts/build-css.sh`)

```bash
#!/usr/bin/env bash
# Build Tailwind CSS for the wiki dashboard
set -e

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_DIR="$(dirname "$SCRIPT_DIR")"
WIKI_DIR="$PROJECT_DIR/src/cems/static/wiki"

# Check for tailwindcss binary
if command -v tailwindcss &>/dev/null; then
  TW="tailwindcss"
elif [ -x "$PROJECT_DIR/tailwindcss" ]; then
  TW="$PROJECT_DIR/tailwindcss"
else
  echo "tailwindcss not found. Install: curl -sLo tailwindcss https://github.com/tailwindlabs/tailwindcss/releases/latest/download/tailwindcss-macos-arm64 && chmod +x tailwindcss"
  exit 1
fi

if [ "$1" = "--watch" ]; then
  echo "Watching for changes..."
  $TW -i "$WIKI_DIR/input.css" -o "$WIKI_DIR/style.css" --watch
else
  echo "Building production CSS..."
  $TW -i "$WIKI_DIR/input.css" -o "$WIKI_DIR/style.css" --minify
  echo "Done: $WIKI_DIR/style.css"
fi
```

## Bugs to Fix During Rewrite

These are existing bugs/gaps found via SpecFlow analysis. Fix them as part of the
rewrite rather than porting broken patterns.

### B1: XSS in conflict resolution (SECURITY)

Line 662 of app.js uses inline `onclick="resolveConflict('${escapeHtml(c.id)}','keep_a')"`.
`escapeHtml` escapes HTML entities but NOT JavaScript string delimiters (single quotes).
**Fix**: Switch to `addEventListener` with `data-*` attributes (same pattern as gap cards
at line 785-787 which already do this correctly).

### B2: Scope toggle class mismatch (BROKEN UI)

Line 929 of app.js toggles `active` class, but CSS line 64 targets `.scope-btn.is-active`.
JS adds `active`, CSS matches `is-active` — they never agree. Currently "works" because
Bulma's `!important` overrides it. After removing Bulma, scope toggle will visually break.
**Fix**: Use consistent Tailwind classes for active state in both JS and HTML.

### B3: Modal has no Escape key handler (ACCESSIBILITY)

Edit modal closes on: Cancel button, X button, backdrop click. No `keydown` listener
for Escape key. Detail panel also has no Escape handler.
**Fix**: Add `document.addEventListener("keydown", ...)` for both modal and detail panel.

### B4: Dead `btn-compile` handler (DEAD CODE)

Lines 600-624 of app.js handle `#btn-compile` but this element doesn't exist in HTML.
**Fix**: Remove the dead code during rewrite.

### B5: Bulma CSS variables used in JS inline styles

`app.js` sets inline styles using CSS variables: `var(--hot)`, `var(--warm)`, `var(--cool)`,
`var(--cold)`. These are custom vars defined in the current CSS. After removing Bulma,
the custom vars in `style.css` disappear unless redefined in `input.css`.
**Fix**: Define all custom properties in `input.css` `@theme` block (already in plan).

### B6: `history.replaceState` prevents browser Back navigation

All view switches use `replaceState`, so browser Back button exits the app entirely.
**Fix**: Flag as follow-up improvement. Keep `replaceState` for now to match existing behavior.

## Dark Mode Strategy

**Decision: Always dark, no toggle.** The app is a developer tool, always used in dark mode.
Hardcode dark colors directly (no `dark:` prefixes needed). Use Tailwind's dark palette
as the only palette: `bg-gray-950`, `bg-gray-900`, `text-gray-100`, etc.

This is the simplest approach — no `prefers-color-scheme` media query, no class toggle,
no duplicate light/dark styles. Just one theme, hardcoded.

If light mode is wanted later, refactor to `dark:` variant at that time.
